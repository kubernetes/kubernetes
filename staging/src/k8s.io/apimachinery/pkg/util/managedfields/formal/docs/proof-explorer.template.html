The ownership contract

      
A manager is full for one item when it claims that item's membership and its entire recursively required core. The same manager must cover every required object branch. Optional nested items have their own lifetimes and can have different full managers.

      
Optional required-bearing maps and the root have independent object scopes. Full ownership of an optional child may belong to a different manager. One required branch of a parent still needs the parent manager to cover that whole branch.

      
For a key-only item, every membership claimant is full. Last-claim deletion follows the same lifetime rule. A full child does not protect a deleted ancestor.

    

    

  

  

    
Values can remain valid while ownership breaks

      
Schema: items is an associative list keyed by name; host and port are required. Bold means required; underlined bold means key.

    

    

      
1
A applies a complete item

        
items:
- name: database
  host: db.example.com
  port: "5432"

        
A is full.

      

      
2
B co-claims only port

        
items:
- name: database
  port: "5432"

        
A remains full. B is partial.

      

      
3
A tries to release port

        
items:
- name: database
  host: db.example.com

        
Full policy: rejected. Raw PR: accepted.

      

    

    
Why the value check is insufficient

      
B still claims port, so both values remain in the candidate. But A would own only host and B only port. The full-manager invariant requires an individual witness, not a coalition. Rejection retains A's original port claim.

      
A handoff first has B acquire the entire required core. Only then can A release it while B remains full.

      

    

  

  

    
SSA-03 / BASE-03: a shared scalar can disappear with its item

      
A creates endpoints: [{name: db, host: old}]. B Updates host to new. A then Applies the same host: new, so both managers own that exact scalar, while A alone owns item membership. A omits the item without force: the list becomes null, the item disappears and both claims are lost.

      
If B acquires the item through Apply, A's omission retains it. Nullable CRD HTTP persists the shared-child deletion; non-nullable validation rejects it and leaves data, claims and resourceVersion unchanged. The shared-omission guarantee needs an enclosing-item lifetime premise even in existing SSA. Trace, control and source boundary.

      

    

    
SSA-06: FieldsV1 rounds one integer item key into another

      
A owns endpoints: [{id: 9007199254740993, payload: old}]. B adds the distinct item {id: 9007199254740992, payload: independent}. The API falsely conflicts against A: reading the exact stored ownership key into float64 rounds it to B's neighbor. Small independent keys 42 and 41 work.

      
Forcing B's request keeps both items and A's old payload, but removes A's claims. The original raw payload claim is checked before decoding. Exact key magnitudes and bytes expose the codec loss; Go's mixed Has/Equals can mask it. Schema, source witnesses and API evidence.

      
Exclusive omission also fails: A owns two adjacent integer-keyed items; B co-applies the upper payload unchanged. A's lower payload is still exclusively A-owned on the wire. When A omits only that payload, B's rounded upper selector falsely protects it. Both item keys remain asserted. Small keys and the large-key history without B remove the payload correctly.

      

    

    
SSA-05: rounded equality loses numeric intent or misses a conflict

      
A owns exact int64 amount: 9223372036854775807. B asserts 9223372036854775808, represented as binary64 263, without force. Alone, the assertion is lost as a false no-op while B acquires the claim. With unrelated note: changed, the new numeric magnitude persists while A and B both retain ownership. An exact int64 change correctly conflicts.

      
Force also leaves A's claim on the rounded change; an exact forced integer change correctly transfers it. Mixed equality and comparator incomparability are nontransitive, with no faithful ordinary-equality quotient. Imported source execution, native Go and real HTTP/GET agree; general IEEE and typed/updater refinement remain separate. Schema, outcomes and proof boundary.

      

    

    
SSA-02: an empty map becomes null despite its claim

      
A replaces settings: {left: old} with settings: {}. Pruning returns settings: null while A still owns map presence. An optional non-nullable schema rejects every retry. A nullable schema stores null; B's identical empty-map intent then conflicts until A repeats and repairs the data.

      
Actual HTTP tests confirm nullable/CEL behavior, unchanged state on rejection, successful empty-map creation, and atomic/defaulted control cases. Detailed trace and schema.

      

    

    
Current SSA: empty-list repetition changes data

      
A previously owns endpoints: [{name: db, host: old}], then applies endpoints: []. The first request removes the field. The second identical request creates the empty list. Actual CRD HTTP execution confirms the data difference and a later ownership bootstrap by before-first-apply.

      
OpenAPI required: [endpoints] or CEL has(self.endpoints) rejects the first request and every identical retry. The populated state, ownership and resourceVersion remain unchanged, although empty-list creation succeeds.

      
Requests, source cause and exact proof boundaries

      

    

    
Resolved: structural consistency and invented ownership

      
Every proper ancestor must be a real container. Scalars cannot have descendants. Structural context no longer invents presence ownership for nonempty maps; actual empty-map claims are compared.

      

    

    
PR #336: fragmentation and partial-owner deletion

      
The raw PR accepts A releasing half its required core while B owns the other half. B's later omission can then delete A's remaining required field. The strict full policy rejects the fragmenting request atomically.

      
    

    
PR #336: required maps and granular lists

      
A direct claim on conn: {} bypasses required-child recursion. Conversely, a known non-null granular list has no direct member claim, including when explicitly applied empty. The PR classifies its supplier as partial. Explicit null creates a direct member and is retained by the classifier; pinned map/list controls verify this distinction.

      

    

    
Source ownership updates cannot add claim paths

      
The complete imported private update body preserves a bound on every manager's paths, including arbitrary finite manager lists, versions, force, errors and lawful map schedules. The remaining field-set premise is exact left-subset preservation by Difference. This phase starts after decoding and actor-field installation.

      
The complete typed field-set map/list visitor bodies now have an atomic-entry certificate: only the whole nonempty scope path is added, child traversal is not invoked, and captured deferred cleanup runs. Existing descendants remain if already present; the empty root is not tracked. Actual insertion/coercion/allocator realization and atomic merge/removal/comparison remain separate BASE-09 obligations.

      

      
The interpreter models comparison references and in-place filtering through the version cache. Its source-backed callback now composes with imported Apply's reset exclusion. Native vendored/pinned Go checks cache filtering and forced removal of B's claim; a claim-growth source mutation fails both the Lean certificate and native witness. General typed/set/filter and complete request refinement remain open.

      

    

    
Recursive Difference preserves exact path origin

      
Go sets store direct members separately from child sets. The complete imported Set.Difference and SetNodeMap.Difference bodies preserve that distinction at every finite depth. Every output path already occurs in the left tree, for every comparator and every Empty() result. Sorting and faithful numeric equality are unnecessary for this weaker guarantee.

      
The recursive adapter now discharges the updater's Difference premise. Native vendored and pinned Go comparisons cover 4,102 pairs, numeric collisions and depth 64. A mutation returning the right matched-child label fails both the source proof and exact native path-origin check. Actual ownership decoding/heap representation and other recursive membership laws remain explicit boundaries.

      

    

    
Conventional reset roots exclude complete claim subtrees

      
The actual excludeFilter.Filter wrapper and both RecursiveDifference bodies are imported. For flat reset roots such as spec, status and metadata, the child source only filters whole root subtrees. Descendant keys are never compared; their numeric collisions do not require a global order assumption.

      
The direct-member proof uses order only in its active field-name domain. Has recognition is now derived through the selected-library source; actual comparison/root/heap representation remain explicit. The native overlay checks 518 pairs, independent-prefix preservation and depth 64. Substituting ordinary Difference must fail both the source proof and native prefix-exclusion check. Object-data restoration and complete Apply/API composition remain separate.

      

    

    
Has and the actual selected-library search are source-bound

      
The complete Has/Less wrappers and Go BinarySearchFunc are imported. A finite-interval proof covers every representable array size and every pure comparator; exact membership additionally requires local ordering and comparator-zero faithfulness. The unsigned midpoint is modeled with its word residue and proved safe even when the signed intermediate sum overflows.

      
The reset filter’s former Has-recognition premise is now derived. Actual field-name comparison, root/heap/ownership representation and complete request composition remain open. Native checks cover 776 lookup queries, 128 Less results and 16 near-limit 32/64-bit midpoint controls; the final-zero-test mutation must fail both source and native membership checks.

      

    

    
Boundaries still requiring separate work

      
Theorems quantify over arbitrary finite normalized model inputs. Go comparisons cover supplied structural schemas, recursive types, composite keys, sets, atomics, empty/null containers and Apply/Update. They are bounded evidence, not a universal Go refinement proof.

      
Conversion, defaults, schema evolution, key defaults, duplicate-list behavior, reset/subresource filters and storage retries are not fully modeled. Admission and CEL are function parameters with composition theorems, not verified interpreters. The stronger required-empty-list rule still requires an ownership representation design.
