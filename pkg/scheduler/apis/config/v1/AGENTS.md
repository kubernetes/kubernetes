# Agent Guide: Kubernetes Scheduler Configuration v1 API (`pkg/scheduler/apis/config/v1`)

This guide provides AI agents and human contributors with an architectural overview, schema breakdown, serialization mechanics, defaulting logic, conversion engine details, generator constraints, and development invariants for the `pkg/scheduler/apis/config/v1` package.

---

## 1. High-Level Overview & Package Purpose

`pkg/scheduler/apis/config/v1` provides the internal package implementation for the GA `kubescheduler.config.k8s.io/v1` component configuration API.

In the Kubernetes scheduler subsystem, configuration is divided across three layers:
1. **External Staging Types (`k8s.io/kube-scheduler/config/v1`)**: Published in `staging/src/k8s.io/kube-scheduler/config/v1`. These represent the public versioned Go structs serialized to/from YAML/JSON configuration files.
2. **Internal Configuration Types (`k8s.io/kubernetes/pkg/scheduler/apis/config`)**: Defined in `pkg/scheduler/apis/config/types.go` and `types_pluginargs.go`. The scheduler engine and plugin framework operate strictly on these unversioned types.
3. **Version Implementation (`pkg/scheduler/apis/config/v1`)**: The bridge between external v1 types and internal types. It registers v1 with `runtime.Scheme`, handles bidirectional conversion, performs semantic defaulting for both global options and plugin arguments, and manages plugin composition.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Configuration File (YAML/JSON)                  │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ (Scheme / Codecs)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ External v1 Types (k8s.io/kube-scheduler/config/v1)                    │
│ - KubeSchedulerConfiguration, KubeSchedulerProfile, Plugins, Args     │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │
                Defaulting Engine (pkg/scheduler/apis/config/v1)
                - Global defaults (parallelism, leader election, etc.)
                - Plugin set merging & feature gate adjustments
                - Plugin argument instantiation & defaulting
                                    │
                                    ▼
                Conversion Engine (pkg/scheduler/apis/config/v1)
                - Auto-generated struct field mapping
                - PluginArgConversionScheme for polymorphic PluginConfig.Args
                                    │
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ Internal Types (k8s.io/kubernetes/pkg/scheduler/apis/config)           │
│ - Validated via pkg/scheduler/apis/config/validation/                  │
│ - Consumed by pkg/scheduler and pkg/scheduler/framework/              │
└────────────────────────────────────────────────────────────────────────┘
```

## 3. External Configuration Schema (`k8s.io/kube-scheduler/config/v1`)

The external types reside in `staging/src/k8s.io/kube-scheduler/config/v1/types.go` and `types_pluginargs.go`.

### 3.1 Top-Level Object: `KubeSchedulerConfiguration`
- **`TypeMeta`**: APIVersion (`kubescheduler.config.k8s.io/v1`) and Kind (`KubeSchedulerConfiguration`).
- **`Parallelism`**: Number of parallel worker goroutines used during scheduling filtering and scoring phases (default: `16`).
- **`LeaderElection`**: Embedded `LeaderElectionConfiguration` controlling multi-instance high availability.
- **`ClientConnection`**: Embedded `ClientConnectionConfiguration` for kube-apiserver communication parameters.
- **`PercentageOfNodesToScore`**: Percentage of cluster nodes considered during feasibility filtering before scoring (default: `0`, dynamically calculated).
- **`PodInitialBackoffSeconds`** & **`PodMaxBackoffSeconds`**: Scheduling backoff parameters for unschedulable pods (defaults: `1s` initial, `10s` max).
- **`Profiles`**: Slice of `KubeSchedulerProfile` defining multi-scheduler configurations and plugin pipelines.
- **`Extenders`**: List of legacy HTTP webhooks for out-of-tree scheduling extension.
- **`DelayCacheUntilActive`**: Boolean delaying cache synchronization until leader election is acquired.

### 3.2 Scheduling Profiles & Plugin Sets
- **`KubeSchedulerProfile`**:
  - `SchedulerName`: Name matching `pod.spec.schedulerName` (default: `default-scheduler`).
  - `Plugins`: Extension points enabling/disabling framework plugins.
  - `PluginConfig`: Polymorphic plugin configuration arguments (`PluginConfig.Args`).
  - `PercentageOfNodesToScore`: Profile-level override for node scoring threshold.
- **`Plugins`**:
  Configures plugins across individual extension points (`PreEnqueue`, `QueueSort`, `PreFilter`, `Filter`, `PostFilter`, `PreScore`, `Score`, `Reserve`, `Permit`, `PreBind`, `Bind`, `PostBind`, `PlacementGenerate`, `PlacementScore`, `PlacementFeasible`, `PodGroupPostFilter`) or globally via `MultiPoint`.
- **`PluginSet`**:
  - `Enabled []Plugin`: Ordered slice of enabled plugins with optional custom `Weight`.
  - `Disabled []Plugin`: List of plugins disabled for this extension point (supports `Name: "*"` to disable all defaults).

### 3.3 Built-in Typed Plugin Arguments
Plugin arguments are defined as distinct typed structs in `staging/src/k8s.io/kube-scheduler/config/v1/types_pluginargs.go`:
- `DefaultPreemptionArgs`: `MinCandidateNodesPercentage`, `MinCandidateNodesAbsolute`.
- `InterPodAffinityArgs`: `HardPodAffinityWeight`.
- `NodeResourcesFitArgs`: `IgnoredResources`, `IgnoredResourceGroups`, `ScoringStrategy`.
- `NodeResourcesBalancedAllocationArgs`: `Resources []ResourceSpec`.
- `PodTopologySpreadArgs`: `DefaultConstraints`, `DefaultingType`.
- `VolumeBindingArgs`: `BindTimeoutSeconds`, `Shape []UtilizationShapePoint`.
- `DynamicResourcesArgs`: `FilterTimeout`, `BindingTimeout`.

## 4. Defaulting Engine (`defaults.go`, `default_plugins.go`)

Defaulting operates recursively on `KubeSchedulerConfiguration` and individual plugin args:

### 4.1 Global Configuration Defaults
- **Parallelism**: Defaults to `16`.
- **PercentageOfNodesToScore**: Defaults to `0` (dynamic threshold based on cluster size).
- **Backoff Timers**: `PodInitialBackoffSeconds = 1`, `PodMaxBackoffSeconds = 10`.
- **Profiling**: `EnableProfiling = true`, `EnableContentionProfiling = true`.
- **Leader Election**:
  - `ResourceLock`: `"leases"` (migrated from `endpointslices`/`configmaps`).
  - `ResourceNamespace`: `"kube-system"`.
  - `ResourceName`: `"kube-scheduler"`.
  - Leases durations defaulted via `componentbaseconfigv1alpha1.RecommendedDefaultLeaderElectionConfiguration`.
- **Client Connection**:
  - `ContentType`: `"application/vnd.kubernetes.protobuf"`.
  - `QPS`: `50.0`.
  - `Burst`: `100`.

### 4.2 Profile & Plugin Defaulting
1. **Single Profile Defaulting**: If `Profiles` is empty, a single profile is generated. If exactly one profile exists with no `SchedulerName`, it defaults to `"default-scheduler"`.
2. **Default Plugin Pipeline (`getDefaultPlugins`)**:
   Default plugins are declared inside `MultiPoint` so that multi-stage plugins automatically bind to all extension points they implement.
   - Standard Plugins:
     - `SchedulingGates`
     - `PrioritySort`
     - `NodeName`
     - `NodeUnschedulable`
     - `TaintToleration` (weight: 3)
     - `NodeAffinity` (weight: 2)
     - `NodePorts`
     - `NodeResourcesFit` (weight: 1)
     - `VolumeRestrictions`
     - `NodeVolumeLimits`
     - `VolumeBinding`
     - `VolumeZone`
     - `PodTopologySpread` (weight: 2)
     - `InterPodAffinity` (weight: 2)
     - `DynamicResources` (weight: 2)
     - `DefaultPreemption`
     - `NodeResourcesBalancedAllocation` (weight: 1)
     - `ImageLocality` (weight: 1)
     - `DefaultBinder`
3. **Feature Gate Injections (`applyFeatureGates`)**:
   - `NodeDeclaredFeatures`: Adds `NodeDeclaredFeatures` to `MultiPoint`.
   - `InPlacePodVerticalScalingSchedulerPreemption`: Inserts `DeferredPodScheduling` immediately *before* `NodeResourcesFit` in `MultiPoint.Enabled` so that policy failures record `DeferredPodScheduling` first for queueing hint retries.
   - `GenericWorkload`: Appends `GangScheduling` to `MultiPoint`.
   - `TopologyAwareWorkloadScheduling`: Appends `TopologyPlacementGenerator` and `PodGroupPodsCount` (weight: 1).
4. **Plugin Merging (`mergePlugins`, `mergePluginSet`)**:
   - Disabling: Evaluates `Disabled` entries (including `*` wildcard).
   - In-Place Replacement: If a user configures a custom version/weight for a default plugin, the default plugin is updated in place, preserving relative extension point execution order.
   - Custom Appending: Custom plugins not in the default list are appended after default plugins.
5. **Plugin Config Generation & Defaulting**:
   - For all enabled plugins in a profile, if no explicit `PluginConfig` entry exists, `setDefaults_KubeSchedulerProfile` constructs a typed `*Args` struct via `GetPluginArgConversionScheme().New(gvk)`, applies its defaults, and appends it as a `runtime.RawExtension`.
   - For existing `PluginConfig` entries, `scheme.Default(args)` is applied in place.

### 4.3 Plugin-Specific Defaults
- **`DefaultPreemptionArgs`**: `MinCandidateNodesPercentage = 10`, `MinCandidateNodesAbsolute = 100`.
- **`InterPodAffinityArgs`**: `HardPodAffinityWeight = 1`.
- **`VolumeBindingArgs`**: `BindTimeoutSeconds = 600`. When `StorageCapacityScoring` feature gate is active, defaults shape curve: `[0% utilization -> score 10, 100% utilization -> score 0]`.
- **`NodeResourcesFitArgs`**: `ScoringStrategy` defaults to `LeastAllocated` with `CPU` (weight: 1) and `Memory` (weight: 1).
- **`NodeResourcesBalancedAllocationArgs`**: Defaults to `CPU` (weight: 1) and `Memory` (weight: 1).
- **`PodTopologySpreadArgs`**: `DefaultingType = SystemDefaulting`.
- **`DynamicResourcesArgs`**: `FilterTimeout = 10s` (if `DRASchedulerFilterTimeout` enabled); `BindingTimeout = 10s` (if `DRADeviceBindingConditions` and `DRAResourceClaimDeviceStatus` enabled).

## 5. Conversion Engine & Polymorphism (`conversion.go`)

### 5.1 The Polymorphic Plugin Argument Problem
`PluginConfig.Args` holds arbitrary plugin configuration data. When converting between external `v1.KubeSchedulerConfiguration` and internal `config.KubeSchedulerConfiguration`, standard reflection cannot know how to deserialize the generic `runtime.RawExtension` into the concrete internal/external Go types.

### 5.2 `GetPluginArgConversionScheme`
`conversion.go` solves this using an isolated conversion scheme:
```go
func GetPluginArgConversionScheme() *runtime.Scheme {
    initPluginArgConversionScheme.Do(func() {
        pluginArgConversionScheme = runtime.NewScheme()
        utilruntime.Must(AddToScheme(pluginArgConversionScheme))
        utilruntime.Must(config.AddToScheme(pluginArgConversionScheme))
    })
    return pluginArgConversionScheme
}
```

### 5.3 Conversion Flow
1. **External v1 -> Internal**:
   - `Convert_v1_KubeSchedulerConfiguration_To_config_KubeSchedulerConfiguration` runs `autoConvert_...`.
   - `convertToInternalPluginConfigArgs` iterates through all profile `PluginConfig` entries.
   - If `Args` is `*runtime.Unknown`, it is left untouched (allowing out-of-tree plugins to pass configuration through).
   - Otherwise, `scheme.ConvertToVersion(args, config.SchemeGroupVersion)` converts versioned plugin args into internal structs.
2. **Internal -> External v1**:
   - `Convert_config_KubeSchedulerConfiguration_To_v1_KubeSchedulerConfiguration` runs `autoConvert_...`.
   - `convertToExternalPluginConfigArgs` iterates through all profile `PluginConfig` entries.
   - Converts internal plugin args to versioned objects via `scheme.ConvertToVersion(args.Object, SchemeGroupVersion)`.

## 6. Code Generation & Generator Constraints

The package uses Kubernetes code generation tools (`k8s.io/code-generator`) driven by tags declared in `doc.go`:

```go
// +k8s:deepcopy-gen=package
// +k8s:conversion-gen=k8s.io/kubernetes/pkg/scheduler/apis/config
// +k8s:conversion-gen-external-types=k8s.io/kube-scheduler/config/v1
// +k8s:defaulter-gen=TypeMeta
// +k8s:defaulter-gen-input=k8s.io/kube-scheduler/config/v1
// +k8s:validation-gen=false
// +groupName=kubescheduler.config.k8s.io

package v1
```

### Generator Tag Breakdown
- `// +k8s:deepcopy-gen=package`: Generates deep-copy methods for all structs in the package.
- `// +k8s:conversion-gen=k8s.io/kubernetes/pkg/scheduler/apis/config`: Target internal package for bidirectional conversion code (`zz_generated.conversion.go`).
- `// +k8s:conversion-gen-external-types=k8s.io/kube-scheduler/config/v1`: Points conversion generator to the external staging package where public types are defined.
- `// +k8s:defaulter-gen=TypeMeta`: Instructs generator to produce default-registering functions for root types implementing `TypeMeta`.
- `// +k8s:defaulter-gen-input=k8s.io/kube-scheduler/config/v1`: Input package for defaulter generation (`zz_generated.defaults.go`).
- `// +k8s:validation-gen=false`: Disables automated validation generation; config validation is centralized manually in `pkg/scheduler/apis/config/validation/`.
- `// +groupName=kubescheduler.config.k8s.io`: Canonical API group name.

### Rules for Generated Files
- **Never edit `zz_generated.*` files manually.**
- Run `make update` or `hack/update-codegen.sh` whenever external/internal types or defaulting functions change.
- `register.go` registers `addDefaultingFuncs` through `localSchemeBuilder` so that manual and generated logic compile independently during generator bootstrapping.

## 7. Package Dependencies & Separation of Concerns

```
                  ┌────────────────────────────────────────┐
                  │ staging/src/k8s.io/kube-scheduler      │
                  │ (External types, client SDKs)          │
                  └───────────────────▲────────────────────┘
                                      │
                         Imports external types
                                      │
┌─────────────────────────────────────┴────────────────────────────────────┐
│ pkg/scheduler/apis/config/v1                                             │
│ - Register, Defaulting, Conversion, Scheme builder                       │
└───────────────────▲──────────────────────────────────▲───────────────────┘
                    │                                  │
       Registers v1 in scheme            Converts to internal types
                    │                                  │
┌───────────────────┴────────────────┐   ┌─────────────┴───────────────────┐
│ pkg/scheduler/apis/config/scheme/  │   │ pkg/scheduler/apis/config/      │
│ (Global runtime.Scheme & Codecs)   │   │ (Internal types & types_plugin) │
└────────────────────────────────────┘   └─────────────────▲───────────────┘
                                                           │
                                             Validates internal config
                                                           │
                                         ┌─────────────────┴───────────────┐
                                         │ pkg/scheduler/apis/config/      │
                                         │ validation/                     │
                                         └─────────────────────────────────┘
```

1. **Staging Boundary**: `staging/src/k8s.io/kube-scheduler` must NEVER import `k8s.io/kubernetes`. External types remain clean and independently consumable.
2. **Validation Decoupling**: Validation (`pkg/scheduler/apis/config/validation`) operates exclusively on internal configuration structs after conversion and defaulting have completed.
3. **Scheme Construction**: `pkg/scheduler/apis/config/scheme` provides the global `Scheme` and `Codecs` instances (`serializer.EnableStrict`), registering both internal and v1 versions.

## 9. Critical Invariants for Agents & Contributors

1. **Polymorphic Plugin Args Safety**:
   Any new in-tree plugin that introduces a configuration struct (`*Args`) MUST:
   - Define external version in `staging/src/k8s.io/kube-scheduler/config/v1/types_pluginargs.go`.
   - Define internal version in `pkg/scheduler/apis/config/types_pluginargs.go`.
   - Register the type in `register.go` of both packages.
   - Implement `SetDefaults_<PluginName>Args` in `defaults.go` if defaulting is required.
   - Add unit tests in `defaults_test.go`.
2. **Preserve Unknown Plugin Args**:
   `conversion.go` must continue to check `runtime.Unknown` to ensure third-party / out-of-tree plugins do not fail conversion when passing unmarshaled custom YAML.
3. **Plugin Ordering Dependencies**:
   - `DynamicResources` MUST precede `DefaultPreemption` so idle resource claims are deallocated before evicting live pods.
   - When enabled, `DeferredPodScheduling` MUST be placed immediately before `NodeResourcesFit` so preemption-disabled node failures trigger the correct queueing hint.
4. **Idempotent Defaulting**:
   All defaulting functions must be idempotent. Calling `SetDefaults_...` multiple times on the same object must produce identical output.
5. **No Circular Imports**:
   Never import `pkg/scheduler` (or plugin implementations) from `pkg/scheduler/apis/config/...`. Plugin names are referenced purely through constants in `pkg/scheduler/framework/plugins/names`.
