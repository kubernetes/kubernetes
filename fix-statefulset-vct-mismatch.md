# Fix: StatefulSet Controller — Endless `FailedUpdate` Loop on Adopted Pod with Mismatched `volumeClaimTemplates`

**Author:** [amanpatelit](https://github.com/amanpatelit)

## Problem

The StatefulSet controller enters an **infinite `FailedUpdate` retry loop** when it adopts a pod that carries a PVC-backed volume for a `volumeClaimTemplate` that no longer exists in `spec.volumeClaimTemplates`.

### When does this happen?

- A pod is adopted by a StatefulSet whose `spec.volumeClaimTemplates` differs from what the pod was originally created with (e.g. cross-set adoption, or a set whose templates have drifted from the pod's actual volumes).
- The pod has one or more `PersistentVolumeClaim`-backed volumes that correspond to templates no longer present in the current set spec.

### Symptoms

```
Events:
  Warning  FailedUpdate  <repeating>  statefulset-controller
           Update Pod foo-0 in StatefulSet foo failed error: ...
```

The StatefulSet never recovers. No pod is deleted or recreated. The error repeats on every sync indefinitely.

---

## Root Cause

### `storageMatches()` only checks one direction

`storageMatches()` in `pkg/controller/statefulset/stateful_set_utils.go` verifies that every VCT in `set.Spec.VolumeClaimTemplates` has a correctly-named volume on the pod. It never checks the reverse — whether the pod has volumes that are no longer in the current templates.

```go
// BEFORE — only checks current VCTs are covered by the pod.
// A pod with extra stale PVC volumes passes this as true.
func storageMatches(set *apps.StatefulSet, pod *v1.Pod) bool {
    for _, claim := range set.Spec.VolumeClaimTemplates {
        volume, found := volumes[claim.Name]
        if !found || ... {
            return false
        }
    }
    return true  // ← stale volumes on the pod are silently ignored
}
```

### `updateStorage()` preserves unknown volumes

`updateStorage()` rebuilds the pod's volume list but deliberately keeps volumes not in the current templates:

```go
for i := range currentVolumes {
    if _, ok := claims[currentVolumes[i].Name]; !ok {
        // volume not in current VCTs — kept as-is
        newVolumes = append(newVolumes, currentVolumes[i])
    }
}
```

### `pod.Spec.Volumes` is immutable

Once a pod is created, the API server rejects any update to `pod.Spec.Volumes`. So when `processReplica` calls `UpdateStatefulPod` on a pod with a stale volume, every attempt fails with a validation error, emitting `FailedUpdate` on every sync — forever.

---

## Fix

### 1. Add `hasStaleVolumes()` — `stateful_set_utils.go`

A new helper that detects PVC-backed volumes on a pod that were generated by this StatefulSet (their claim name matches the pattern `<templateName>-<setName>-<ordinal>`) but whose template name is no longer in `spec.volumeClaimTemplates`.

```go
func hasStaleVolumes(set *apps.StatefulSet, pod *v1.Pod) bool {
    ordinal := getOrdinal(pod)
    if ordinal < 0 {
        return false
    }
    validTemplates := make(map[string]bool, len(set.Spec.VolumeClaimTemplates))
    for _, tpl := range set.Spec.VolumeClaimTemplates {
        validTemplates[tpl.Name] = true
    }
    for _, vol := range pod.Spec.Volumes {
        if vol.PersistentVolumeClaim == nil {
            continue
        }
        // Only flag volumes whose claim name matches this set's naming pattern.
        if vol.PersistentVolumeClaim.ClaimName != getPersistentVolumeClaimName(
            set, &v1.PersistentVolumeClaim{ObjectMeta: metav1.ObjectMeta{Name: vol.Name}}, ordinal,
        ) {
            continue
        }
        if !validTemplates[vol.Name] {
            return true
        }
    }
    return false
}
```

**Key design decisions:**

- Volumes from other StatefulSets (wrong claim name pattern) are never flagged — safe for cross-set scenarios.
- Non-PVC volumes (ConfigMap, Secret, HostPath, etc.) are ignored entirely.
- A pod with an unparseable ordinal returns `false` — fail safe.

### 2. Delete instead of update — `stateful_set_control.go`

In `processReplica`, after the healthy-pod early-return, check for stale volumes before attempting `UpdateStatefulPod`. If found, delete the pod so it gets recreated cleanly on the next sync.

```go
// BEFORE
if identityMatches(set, replicas[i]) && storageMatches(set, replicas[i]) && retentionMatch {
    return false, nil
}
replica := replicas[i].DeepCopy()
if err := ssc.podControl.UpdateStatefulPod(ctx, updateSet, replica); err != nil {
    return true, err  // ← loops forever if Volumes are immutable
}

// AFTER
if identityMatches(set, replicas[i]) && storageMatches(set, replicas[i]) && retentionMatch {
    return false, nil
}

if hasStaleVolumes(set, replicas[i]) && !isTerminating(replicas[i]) {
    // pod.Spec.Volumes is immutable — delete and let the next sync recreate it
    if err := ssc.podControl.DeleteStatefulPod(set, replicas[i]); err != nil {
        return true, err
    }
    return true, nil
}

replica := replicas[i].DeepCopy()
if err := ssc.podControl.UpdateStatefulPod(ctx, updateSet, replica); err != nil {
    return true, err
}
```

## Tests

### Unit test — `TestHasStaleVolumes`

Covers all cases for the new helper:

| Scenario | Expected |
|----------|----------|
| Freshly created pod, all VCTs present | `false` |
| Pod with no volumes | `false` |
| Pod whose VCT was removed from the set | `true` |
| Pod with a PVC volume from a *different* set | `false` |
| Pod with an unparseable ordinal | `false` |

### Integration test — `TestDeletesAdoptedPodWithStaleVCTVolumes`

1. Scale up a 1-replica StatefulSet to Running+Ready.
2. Inject a stale `oldvol` PVC-backed volume onto `foo-0` in the indexer (simulating an adopted pod).
3. Run one `UpdateStatefulSet` sync.
4. Assert the pod was **deleted** from the store — not left alive to retry `UpdateStatefulPod` forever.

### Run the tests

```bash
make test WHAT=./pkg/controller/statefulset GOFLAGS=-v
```
